# ADR-0012：批量上传由客户端顺序编排单 Document 命令

状态：已接受
日期：2026-08-30

## 背景

M1 已建立唯一的单 Document 上传边界：每次 `POST /api/v1/documents` 只接收一个文件，服务端流式暂存并执行大小、签名与 MIME 校验，在同一数据库事务中创建不可变 Document 和 queued ProcessingJob；同租户原始 SHA-256 完全重复时返回既有 Document，且不创建第二个 Job。对象提交失败时，元数据通过已测试的补偿路径回收。

M2 第四切片需要一次选择多个 Document，并让用户逐项看到成功、重复或失败结果。若新增服务端批量 multipart、Batch 实体或批次事务，会复制现有上传入口、放大请求内存和失败面，并制造“部分成功是否回滚”的第二套语义。批量选择只是交互编排，不是新的领域事实。

## 决策

Web 在一次选择中接受 1–20 个文件，按用户选择顺序逐个调用现有 `POST /api/v1/documents`。服务端 OpenAPI、数据库 Schema、Document、ProcessingJob 和对象存储协议保持不变；单 Document 命令仍是上传、校验、精确判重和入队的唯一写入位置。

每次选择创建一个只存在于当前页面内存的临时反馈列表，使用选择序号作为本批次内的稳定身份。每项状态只允许：

- `waiting`：已选择，等待本地预检或上传；
- `uploading`：当前唯一正在发送的文件；
- `queued`：服务端创建了 Document 与 queued Job；
- `duplicate`：服务端返回同租户既有 Document，未创建新 Job；
- `rejected`：本地明确拒绝或该次服务端请求失败。

一次只允许一个 `uploading` 项。前一项进入终态后才处理下一项；中间项失败不得回滚、取消或阻止已经成功或尚未处理的其他项。列表顺序始终与用户选择顺序一致。

### 容量与校验边界

- 一次选择最多处理前 20 个文件；第 21 个及以后必须保留在反馈列表并明确标记 `batch_file_limit_exceeded`，不得静默丢弃。
- 单文件上限继续为 20 MiB。浏览器可在发请求前把明显超限文件标记为 `document_too_large`，但这只是减少无效传输；服务端仍是大小、空文件、扩展名、签名与 MIME 的唯一权威校验边界。
- 不增加批次总字节上限。顺序发送保证服务端任一请求仍只承载一个最多 20 MiB 的文件。
- 不支持目录上传、拖拽目录、自动拆分 PDF、自动重试、自动取消、后台续传或持久化批次状态。

### 重复、失败与恢复

- 选择中两个字节完全相同的文件也按顺序请求：首项可创建 Document，后项由现有同租户 SHA-256 规则返回 `duplicate_document`；客户端不得预先合并或跳过。
- `duplicate` 是成功识别既有资源的独立终态，不伪装成新入队成功；仅显示服务端允许返回的同租户 Document ID，不显示路径、哈希或原始内容。
- 每次失败只绑定当前项的稳定安全错误码与消息。网络异常使用本地通用消息，禁止展示响应正文、堆栈、存储路径或 Provider 信息。
- 网络失败后仍继续下一项。用户可通过重新选择文件发起新批次；服务端 SHA-256 判重使“响应丢失但实际已提交”的重试收敛为既有 Document。
- 批次运行时禁用文件选择，避免两个客户端编排器交错。新选择会替换已经结束的上一份临时反馈，但不修改任何已创建 Document 或 Job。

## 验收不变量

- 同一批次的请求严格串行并保持原选择顺序；任意时刻最多一项为 `uploading`。
- 每个服务端成功项恰好对应一个 Document 和一个 queued ProcessingJob；重复项和失败项不产生第二个 Document、Job 或临时元数据残留。
- 中间项失败后仍处理后续合法项；不同项之间没有事务性回滚。
- 20 项上限和 20 MiB 单项上限在 UI 中显式可见，超限项保留为可访问的失败行。
- 每行同时以文字显示文件名、大小、状态及必要原因；批次汇总通过 `aria-live` 或等价机制可感知。键盘、768px 和等效 200% 缩放布局不能丢失文件选择或逐项结果。
- 完成后只刷新一次权威收件箱列表；Document/Job 状态仍从服务端读取，临时反馈列表不能成为第二数据源。

## 结果

- 用户可以一次选择多个文件并获得稳定、逐项、可恢复的反馈。
- 现有单 Document 命令、精确判重、租户隔离、对象补偿和性能边界被直接复用，不产生平行 API 或持久化批次状态。
- 服务端领域、数据库和 OpenAPI 无需因 UI 编排而改变；后端增加的验收只验证独立命令在中间失败后仍可继续调用且没有部分残留。

## 非目标

- 服务端批量上传端点、Batch 表、批次事务或批次级回滚；
- 并行上传、自动重试、暂停/恢复、跨页面持久化或后台上传；
- 内容近似合并、客户端 SHA-256 判重或任何 OCR/模型调用；
- 独立 Link 调整、M3 邮箱附件摄取或真实外部系统联调。
