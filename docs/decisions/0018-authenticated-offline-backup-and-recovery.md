# ADR-0018：认证的停机备份与完整恢复演练

状态：已接受；实现与 1,000 Document 完整本地演练均已通过
日期：2026-08-31

## 背景

M1 的最小恢复冒烟证明了 SQLite、对象目录和主密钥可以在停机后复制并恢复，但它不能直接作为 M4 的完整恢复结论。现有工具只核对上传 Document 与 DocumentPage，未覆盖 M3 的邮件原文和附件对象；主密钥与密文被复制到同一个备份目录；清单只有无密钥 SHA-256；`-offline-confirmed` 也不能证明应用进程已经退出。恢复过程中断还可能留下可被误启动的半恢复目标，旧 Session 则会在恢复后继续有效。

M4 需要用至少 1,000 个具有实际合成对象文件的 Document，在参考环境中证明完整恢复时间不超过 30 分钟。该演练必须验证当前 Clean Slate 数据模型，而不是保留旧清单、旧工具入口或兼容分支。

## 决策

### 新恢复集合与清单

恢复集合由两个必须独立控制的部分组成：

1. 数据备份包：SQLite 快照、已提交对象和 `manifest.json`；
2. 既有主密钥的独立托管副本：不进入数据备份包，由操作者通过受保护文件单独提供。

数据包单独不可恢复。工具不得复制、打印或在清单中记录主密钥、可恢复密钥材料或密钥哈希。`manifest.json` 使用从主密钥按固定域分离规则派生的 HMAC-SHA-256 认证；`verify` 和 `restore` 均必须同时取得独立主密钥并先验证认证标签。主密钥路径不得位于数据备份包内。数据包与独立密钥副本必须使用不同的访问控制和存储故障域，工具只能验证内容匹配，不能把同一目录误称为独立托管。

清单规范固定为 `smart-bill-manager-backup/2`，不解析旧 M1 清单。清单至少冻结：128-bit 随机 `backup_set_id`、创建时间、迁移集合身份、SQLite 文件记录、完整性检查、外键检查、当前 Schema 身份、全部表数量、审计链 SHA-256、Document 数量、对象引用行数、唯一物理对象数，以及全部已提交对象的相对路径、字节数和 SHA-256。backup、verify、restore 及演练后 API/数据库受保护结果必须携带同一集合身份；最终仓库证据只保存“身份相等”布尔值。CLI 不输出完整清单、文件路径、对象哈希、Cookie、密码、Provider 密钥或业务字段。

### 停机一致性与唯一对象集合

应用、Owner 初始化命令、性能种子与备份工具共享数据库旁的本地运行锁。运行中的应用持锁时，备份必须立即拒绝；操作者声明不能替代该检查。数据库、对象文件和主密钥不得有第二个硬链接；备份输出不得位于数据库父目录、对象根或迁移集合内。备份在持锁期间完成 WAL `TRUNCATE` checkpoint、排他 SQLite 事务和对象检查，且只接受空 `staging/` 与空 `trash/`。源目录含符号链接、特殊文件、未知顶层项、未提交对象或待协调删除时必须失败。

数据库到对象的权威引用集合固定为：

- 所有 `documents.storage_key + sha256 + size_bytes`；
- 所有 `document_pages.derived_image_storage_key + sha256`；
- 所有 `email_messages.raw_storage_key + raw_sha256 + raw_size_bytes`；
- 所有非空 `email_attachments.storage_key + sha256 + size_bytes`。

同一物理 key 被邮件附件与其 Document 共同引用时按 key 去重；所有引用必须给出相同 SHA-256，已知大小也必须相等。任一缺失、错哈希、错大小、不安全 key、同 key 冲突或无数据库引用的已提交文件都使备份失败。只复制精确等于该唯一引用集合的 `objects/`，不复制 `staging/`、`trash/` 或运行锁。

SQLite 必须同时通过完整 `PRAGMA integrity_check` 与空 `PRAGMA foreign_key_check`。当前迁移目录按排序后的文件名和内容生成身份；数据库 `schema_migrations` 与迁移目录必须精确对应，SQLite `sqlite_schema` 另生成确定性身份。备份、验证和恢复都使用同一已冻结迁移集合，不接受旧数据库探测或迁移。

### 崩溃安全恢复与激活

恢复只接受不存在的数据库、对象根和主密钥目标，不覆盖空目录或既有文件。数据库、对象根和主密钥先分别写入各目标文件系统内的随机 staging 路径；工具在 staging 上完成清单认证、文件、数据库、对象引用和独立主密钥复核后，才进入激活阶段。

激活前在数据库目标旁创建 owner-only、单硬链接、版本化内容为 `incomplete` 的持久 `restore-state`。应用启动在取得运行锁前后都检查该状态；incomplete、未知、损坏、符号/硬链接、宽权限、或 complete 状态与数据库不成对时一律拒绝。跨文件系统发布任一步失败或进程中断时，incomplete 状态保持存在，部分目标不得启动或复用。三部分全部发布、Session 清零、离线后检查和同步完成后，工具在同目录创建并 `fsync` 独立 complete 文件，再以原子 rename 替换状态并同步父目录；成功状态永久保留，不以删除目录项表示完成。complete 文件同步失败时 durable incomplete 不得被改写。

恢复副本在首次应用启动前删除全部 Session。离线复核先证明原始快照与清单完全相等；会话失效后再次证明除 `sessions = 0` 外的表数量、Schema、审计链和对象集合仍与清单一致。旧 Cookie 必须返回未认证，新登录必须成功。Session 变化不伪装成原始快照的逐字相等。

### 固定 M4 演练数据与 RTO

参考演练只使用回环 synthetic Provider、`.invalid` 身份和纯合成 MIME/图片字节，不访问真实 Provider、邮箱、云服务或外部账号。冻结数据集恰好包含 1,000 个 Document：

- 997 个在未配置 Provider 时明确进入 `failed/provider_config_missing` 的普通上传 Document；
- 1 个由合成邮件非空附件创建、同样在无 Provider 时进入 `failed/provider_config_missing` 的 Document；
- 1 个已确认且形成一个 Payment Fact 的 Document；
- 1 个备份时持有有效租约并存在一个 `running` AiRun 的 Processing Document。

数据集另含一封合成邮件原文、一个非空归档附件、一个由邮件附件共享原件的 Document，以及恰好两个 DocumentPage（已确认上传与备份边界上的 Processing 上传各一个）。无 Provider 的 998 个失败任务在页面规范化前终止，不能伪造 Page 行。最终对象关系固定为 1,004 条引用和 1,003 个唯一物理对象；所有 Document 都必须具有真实合成原件，不允许只写数据库行。成功前还必须证明 `staging/` 与 `trash/` 为空。

30 分钟使用单调流程起点加持久化 UTC 时间共同计量。先创建数据包，再以 O_EXCL 写入不可重置的时钟；时钟必须早于首次独立认证 verify，随后覆盖：验证同一 `backup_set_id`、复制到新目标、离线清单对账、会话失效、启动应用、`ready`、旧 Cookie 拒绝和新登录。在继续租约任务前必须先证明原快照 Fact/Document 可查询且上传与邮件对象可鉴权下载；全部读取完成后再读取目标 Job，只有它仍为 `processing` 且 attempt 与备份前相等才形成线性化屏障。随后才允许过期租约接管、旧 `running` AiRun 全库唯一转为 `failed/lease_expired`、Job attempt 恰好增加一次、继续处理到 `needs_review`，以及最终确认后恰好新增一个 Fact。任一步超过 30 分钟均失败。

恢复副本首次启动后的预期增量必须单独对账，不能继续声称整个数据库与备份清单逐字相等。备份前快照冻结全部既有非 Session 行的确定性摘要：998 个失败 Document/Job、目标 Job 的唯一旧 `running` AiRun、已确认 Document 的唯一旧 `succeeded` AiRun 和全部其他稳定行都必须精确；目标 Document/Job/旧 AiRun 只排除明确可变列，其他行完整纳入。恢复后摘要必须相等。目标新 AiRun 必须复用旧请求的 Provider 版本/指纹、模型、Prompt、各 Schema/Mapper/输入版本和请求哈希；新增行只能闭合到该新 AiRun、唯一 Claim、ReviewDecision、Payment、Evidence/Validation/Origin、可选重复候选及其逐项决定和一个确认审计事件；其他 Job/AiRun 或业务链变化均失败。回环 Provider health 必须精确绑定 exercise UUID、模型、挂起模式、实例和 0→1 计数。所有会写业务数据的演练阶段先排他保留结果文件。最终证据只提交安全聚合、相等性布尔值、耗时和状态计数，不提交身份值、数据包、数据库、对象、独立主密钥、受保护状态文件、Cookie、原始响应或日志。

### RPO 与删除边界

本切片演练恢复同一个停机快照，RPO 固定为 0：从备份完成到恢复验证之间不得写入业务数据或执行删除，因此不存在需要重放的快照后变更。Provider 密文在数据包中的最长残留仍受 30 个日历日保留上限约束。

真实灾难恢复若允许非零 RPO，必须在生产发布门禁前提供独立、认证且单调的快照后租户删除/凭据撤销登记，并在激活前重放；当前本地演练不得虚构该外部运行条件，也不得恢复真实账号或真实 Provider。该要求属于生产恢复方案，不为本切片增加第二个应用内数据源。

## 失败边界

以下任一情况必须硬失败，不能降级为警告、部分成功或自动兼容：

- 应用运行锁被占用、WAL checkpoint busy、排他事务失败或操作者未确认停机；
- 数据包内含主密钥，主密钥位于数据包内、权限过宽、格式无效，或 HMAC 认证失败；
- 旧/未知清单版本、未知/重复字段、尾随 JSON、重复/乱序/越界记录、不安全路径或符号链接；
- 迁移集合、`schema_migrations`、SQLite Schema、完整性检查或外键检查不一致；
- 四类对象引用任一缺失、哈希/大小冲突，存在未引用对象，或 `staging/`、`trash/` 非空；
- 恢复目标任一已存在，staging 复核失败，激活状态缺失/未知/损坏/孤立，或恢复后旧 Session 未全部失效；
- Document 不等于 1,000、真实对象不完整、备份前 Job/Fact/AiRun 形状不符；
- `ready`、新登录、查询、鉴权下载、租约恢复、AiRun 收口或最终确认任一失败；
- attempt/version 增量、Fact 增量、稳定行摘要、闭合新增链、表数量、对象清单、审计链或预期启动后增量不符；
- 总恢复时间超过 30 分钟，或证据包含凭据、业务字段、原始响应、日志、数据库或对象内容。

## 非目标

- 在线/增量备份、连续归档、跨地域复制、云备份服务或自动故障转移；
- 非零 RPO 下的生产删除登记、真实灾难切换或真实部署；
- 旧 M1 清单、旧工具参数、旧数据库、旧对象布局或旧任务状态兼容；
- 真实 Provider/邮箱/外部账号联调、正式模型正确率评测、密钥创建或变更；
- 把备份数据包、独立主密钥或恢复临时产物提交到 Git。

## 验证要求

- 单元/集成测试覆盖四类对象与共享 key、精确对象集合、完整/外键/迁移身份、HMAC、随机备份集合身份、严格清单、路径/符号/硬链接、输出与源隔离、运行锁、空 staging/trash、会话失效和持久崩溃状态；
- 错哈希、错大小、缺失/多余对象、同 key 冲突、错误主密钥、篡改清单、已有目标和部分恢复必须显式失败；
- 纯合成控制器必须生成恰好 1,000 个实际 Document 原件、2 个规范化 Page、1,004 条对象引用和 1,003 个唯一物理对象，并以一个恢复时钟覆盖完整 RTO；
- 恢复后验证旧 Cookie 失败、新登录成功、查询和两类下载成功、租约只接管一次、旧 AiRun 收口且 Fact 不重复；
- 完整门禁包含后端测试/vet/build、脚本静态检查、关键不变量、覆盖率、diff、敏感信息、大文件、临时产物、容器与进程残留审查，以及安全聚合证据 JSON。
