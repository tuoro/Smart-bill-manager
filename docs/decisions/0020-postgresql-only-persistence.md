# ADR-0020：PostgreSQL 唯一关系持久化

状态：已接受并完成本地验收
日期：2026-08-31

## 背景

当前 Clean Slate 系统以 SQLite 完成了 M1～M4 前两个切片的本地功能与恢复演练。产品负责人现已明确后续目标包含单位集中部署、多用户并发和长期规模化使用。继续把最终发布、备份恢复和运行质量门禁绑定到单文件数据库，会在进入真实联调前形成一次可预见的二次迁移。

本决策不是用更换数据库掩盖慢查询。重复检测必须命中索引，洞察仍必须在数据库内聚合并使用稳定分页；这些数据访问不变量在 PostgreSQL 中继续成立。切换的依据是集中部署的并发、运维、备份和扩展边界，而不是 10,000 条记录本身。

## 决策

### 单一关系数据源与 Clean Slate 切换

- PostgreSQL 17 成为当前产品唯一关系数据源。本地对象文件仍是唯一对象存储实现，本切片不同时引入 S3 或其他远端对象存储。
- 最终代码树只保留 PostgreSQL 适配器、驱动、迁移、配置和运行入口；删除 SQLite 驱动、适配器、迁移、数据库文件参数、运行锁和发布卷，不保留双写、运行时选择、兼容包装或第二测试数据源。
- 不读取、导入或迁移任何既有 SQLite 数据。PostgreSQL Schema 从新的 `0001` 建立空库；历史 Git 提交足以追溯旧实现，不在当前产品目录保留可执行兼容链路。
- ADR-0017 的洞察业务规则继续有效，但其 SQLite 事务实现由本决策替代；ADR-0018 的 SQLite 数据包与恢复实现只保留为历史证据，必须以 PostgreSQL 备份恢复重新验收；ADR-0019 的发布门禁必须在 PostgreSQL 候选上重跑后才能完成。

### 连接、凭据与租户边界

- Go 端使用一个固定、直接的 PostgreSQL 驱动实现 `database/sql` 边界；驱动版本进入 `go.mod`、`go.sum` 和发布输入身份，不增加 ORM 或查询生成器。
- 数据库地址、端口、库名和用户名是普通配置；密码只从 owner-only 文件读取并在内存中组装连接配置，不进入 argv、环境变量、Compose 展开结果、日志、错误、文档或仓库证据。
- 本地 Compose 的 PostgreSQL 只存在于 internal 网络且不发布宿主端口。`local` 验收允许该隔离网络内不启用 TLS；未来跨主机或生产连接必须在独立发布门禁冻结 `verify-full`、CA 和凭据托管，不能继承本地豁免。
- 每个查询和写入继续显式携带 `tenant_id`；切换数据库不引入全局租户、隐式会话租户或数据库旁路。

### Schema、迁移与事务语义

- PostgreSQL `0001` 必须完整表达当前 Clean Slate Schema、复合租户外键、CHECK、不可变历史、局部唯一索引和触发器约束；时间使用 `timestamptz`/`date`，JSON 使用 `jsonb` 并保留封闭业务校验，金额仍为安全范围内的整数最小单位。
- 迁移只能由显式迁移入口执行；常规 API 运行身份不得获得建表、改表或删除 Schema 的权限。迁移集合与数据库中已应用身份必须精确一致，未知、缺失、乱序或内容漂移均拒绝启动。
- 多查询只读响应使用一个 `REPEATABLE READ READ ONLY` 事务，保证 Trip 校验、洞察汇总与当前页来自同一快照。
- 财务决定、审核确认、分配、归属、报销、任务租约和删除使用显式行锁、唯一约束和适用的 `SERIALIZABLE` 事务。`40001`、`40P01` 和陈旧版本统一映射为稳定并发冲突，不吞错、不把部分写入伪装为成功。
- Worker 领取使用 PostgreSQL 行锁语义实现多进程安全竞争；不得依赖 SQLite immediate 全库写锁，也不得用进程内互斥代替数据库约束。
- 所有参数使用驱动绑定；禁止拼接不可信 SQL。重复检测仍先使用租户和指纹 band 索引缩小集合，再在应用层执行确定性距离判断；洞察继续数据库聚合与 keyset 分页，禁止恢复为全量载入 Go 内存。

### 备份恢复与发布边界

- M4 继续采用停写、RPO 0 的本地恢复演练，但数据库载荷改为固定 PostgreSQL 17 工具生成的自包含 dump；禁止复制 PostgreSQL 数据目录、WAL 或 Docker volume 作为应用级备份格式。
- 认证清单继续与主密钥分离，并覆盖 dump、精确对象集合、迁移身份、Schema 身份、表数量和审计链。恢复只进入全新 PostgreSQL 数据库和全新对象目标；完成严格复核后失效全部旧 Session。
- `pg_dump`、`pg_restore` 与服务端 major 版本必须固定并校验。数据库凭据、连接串、对象路径、业务字段和原始命令输出不得进入仓库证据。
- 既有 1,000 Document 纯合成数据集、30 分钟 RTO、对象精确对账、任务续跑一次和稳定行摘要边界保持不变，并在 PostgreSQL 实现上重新演练；历史 SQLite 结果不得替代。
- 最终 Compose 至少包含 app 与 PostgreSQL 两个受限服务。数据库使用独立持久卷、健康检查、CPU/内存/PID 约束和停止窗口；app 就绪必须同时证明 PostgreSQL 可用与 Worker 已运行。

## 实施切片与通过条件

1. 更新权威范围、架构、数据模型、备份恢复和验收文档，明确历史 SQLite 证据已被当前目标替代；
2. 新增并锁定 PostgreSQL 驱动，重建 PostgreSQL `0001`，实现显式迁移入口与唯一 PostgreSQL 适配器；
3. 逐模块迁移身份、文档、任务、Provider、Claim/Review/Fact、重复检测、分配、邮件、行程、报销、洞察和删除事务，并删除 SQLite 产品链路；
4. 所有适配器与 HTTP 集成测试只连接受限的临时 PostgreSQL 17 容器；覆盖事务回滚、序列化冲突、死锁分类、租户隔离、多 Worker 竞争、同快照读取与 Schema 漂移；
5. 重新执行 10,000 Fact/Document 性能、内存稳定、1,000 Document 认证备份恢复、完整 Go/Web/Node、覆盖率、关键不变量和浏览器门禁；
6. `go.mod`、源码、Compose、当前运维文档和发布资产中不存在 SQLite 运行依赖或第二数据源；历史 ADR/证据必须明确标注历史身份，不能被运行时引用；
7. 安全聚合证据与 PostgreSQL 候选一致，临时凭据、容器、网络、卷和原始报告销毁后创建独立本地提交，不推送。

## 明确不包含

- SQLite 数据导入、旧 Schema 探测、双数据库运行、灰度双写或回滚到 SQLite；
- 托管 PostgreSQL、云数据库、跨主机 TLS、HA、流复制、自动故障转移、连接代理或读副本；
- S3/对象存储迁移、真实邮箱或 Provider 联调、真实模型评测、部署、发布、付费或远端资源；
- 以数据库切换为理由改变 Source→Claim→Fact、人工审核、租户、金额、AI 提取或现有产品功能。

## 后果

- 当前未完成的 M4 本地发布切片必须暂停在 PostgreSQL 迁移之后，SQLite 候选不能再被宣称为当前发布基线。
- 迁移工作量显著高于替换连接字符串，但能在真实外部联调和生产数据进入系统之前一次性关闭双数据库与旧数据风险。
- PostgreSQL 驱动是新增依赖；在产品负责人单独授权下载并锁定前，只能完成文档、现有代码审查和不需要该依赖的准备工作。
