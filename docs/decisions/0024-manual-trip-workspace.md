# ADR-0024：人工出差行程与行程凭证分离

状态：已接受并完成本地切片验收；未提交、发布或升级用户实例
日期：2026-09-04

## 背景与范围

用户确认行程是人工建立的一次出差/费用归集容器，一次可含多张机票、住宿及其他费用；授权恢复手动创建/编辑、唯一时间匹配自动归属、重叠待人工和人工选择优先。本 ADR 替代 ADR-0015 关于容器创建、字段和自动归属的规定，保留凭证审核、租户、不可变历史及新报销工作流。

只实施和本地验收，不推送、发版或修改用户运行实例。不恢复旧代码/数据库/API、旧二值报销、坏账锁、旧导出或级联删除业务数据。

## 实体与来源

- `Trip` 是人工费用容器，不是模型 Fact。Owner/Finance 新增和编辑名称、开始/结束日期、IANA 时区与可选备注；不强制目的地，不把名称伪装成票面目的地。
- `TripEvidence` 是审核后的行程凭证 Fact，仍走原图、最小中文指令、本地校验、Review 和字段来源链。模型契约的 `document_type=trip` 继续表示凭证，确认后不再新建费用容器。
- 一容器可关联多个 Payment、Invoice 和 TripEvidence，每个 Fact 同时最多归属一个活动容器，可显式移动/撤销。凭证使用独立材料关系，不给它虚构金额，也不计入费用汇总/报销。
- 手工行程不伪造 Document、AiRun、Claim、ReviewDecision 或 FactFieldOrigin；Payment/Invoice 金额、审核和来源不变。Reviewer 只审核凭证，材料归集由既有财务权限用户在行程页完成。

## 管理与时间

- 新增/编辑提交完整管理字段与幂等键、期望版本和必填理由。名称 1～500 字符（容纳当前版本已有显示名称）、备注不超过 2,000 字符、理由 1～500 字符；日期必须真实有效且结束不早于开始，时区必须是有效 IANA 标识。
- 范围包含所选时区内的完整起止自然日，等价于开始日零点到结束日次日零点的半开区间；不保留旧 UI 结束日 23:59:59 的最后一秒缺口，不使用服务器隐式时区。
- 当前容器行是管理字段唯一查询来源；不可变管理决定保存 actor、完整管理快照、版本、理由、请求 hash 和审计身份。修改容器不改票面 Fact 或已提交报销快照。
- 使用现有 SERIALIZABLE、有限重试、幂等及期望版本，冲突明确失败且前端保留草稿。

## 自动归属与人工优先

- 仅已确认、未删除 Payment 按精确交易时间匹配容器的当地日期范围。恰好一个命中才自动归属；零个命中保持未归属；多个命中为重叠待分配，不按最近/最短/最新挑选。
- 新增、编辑、删除容器，确认 Payment 及用户恢复自动时重算受影响支付；使用 SQL 索引条件和 keyset 分批，不全量载入内存。
- 自动决定使用 `trip-time-attribution/1` 并追加不可变 Decision/Assignment；只替换自动 Link，不原地修改历史。
- 复用费用 Fact 的现有聚合 `version`，不创建第二版本状态表；人工请求同时校验期望 Link 与版本，避免未归属状态反复后的并发空隙。人工 assign/move 标为人工，unassign/“保持无归属”标为禁止自动；只有显式“恢复自动归属”才清除偏好并重算。
- ±3 日和关联发票信号仍只是建议。Invoice 与 TripEvidence 不按日期自动归属。候选清晰展示自动/人工/保持无归属、无匹配/重叠原因。

## 前向迁移与历史

- 新增 `0002`，保持 `0001` 字节和账本不变，不读旧架构数据库、不清库。
- 保留当前 `trips` ID 作为容器；全部原票面字段、Review、版本及软删除信息复制到 `trip_evidence_facts`，FieldOrigin 的 Trip 外键改指凭证。原 Claim、Evidence、Review、费用关联、决定和报销快照不改号、不改历史值。
- 原目的地仅初始化容器显示名称，明确标为迁移来源，不声称是票面行程标题。旧容器日期保留、时区为空，用户设置时区前不参与自动归属；不静默补上海时区。
- 活动历史容器与对应凭证建立明确标为迁移来源的关联；已删除事实不重新激活。所有原费用决定保留人工属性，包括撤销后的无归属偏好；迁移不重算、不合并、不移动。
- 新空库和 v0.3.4 升级得到相同 Schema；重复迁移不重复复制，失败整体回滚。

## 删除、报销和恢复

- 删除容器与删除凭证使用不同资源操作。容器删除只软删容器并终止活动费用/材料关系，不删除对端 Fact/原件/报销。凭证删除只软删凭证并终止其材料关联；历史同 ID 不能误伤容器或费用。
- 新报销快照保存行程名称、日期、时区和版本；旧快照显示值及原 hash 保留，不重算历史 hash。容器编辑应使旧预检过期，不改变已提交记录。
- 备份继续动态覆盖全部 PostgreSQL 表和对象集合；同步恢复演练的稳定表与 Fact 计数。旧版备份由对应版本工具恢复后再升级，不放宽认证或 Schema 身份。
- Schema 指纹按可见列顺序编号，忽略 `DROP COLUMN` 留下且逻辑恢复不保留的物理槽位空隙；列名、顺序、既有类型定义、空值/默认值和约束等校验保持。不得改写已有认证清单来通过恢复。
- 审计 metadata 仅记动作、版本、来源类别和数量，不记名称、日期、备注、理由、票面或凭据；业务快照只存在租户私有历史中。

## 验收与失败边界

1. 无上传/Provider 创建编辑；非法字段/日期/时区、幂等冲突、过期版本、跨租户和角色失败均零写入。
2. 两张凭证确认只生成两份材料，不生成容器；能关联同一手工行程、移动/撤销，材料不影响金额。
3. 支付覆盖起止边界、次日边界、时区/DST、零/一/多命中、容器变更、人工优先、恢复自动及并发。
4. 容器/历史/审计/自动关系任一步失败整体回滚；活动唯一、不可变历史、状态版本和租户 FK 由数据库验证。
5. 合成 v0.3.4 升级覆盖活动/已删除 Trip、来源、费用关联、人工撤销及三种报销状态，保留 ID/字段/快照 hash；容器与凭证同 ID 删除互不误伤。
6. 重验受影响审核、报销、洞察、删除、恢复、Web check 与浏览器；键盘和响应式保持。
7. 完整 diff、敏感信息、临时产物与资源检查；原始报告仅留本轮隔离目录，未运行门禁明确记录，不改绑历史通过结果。

## 本地验收结果（2026-09-04）

受限 PostgreSQL 17 全量 Go 测试 470 项通过、零跳过，151 项关键不变量均从该轮实际通过事件核对；领域/应用与基础设施/接口层覆盖率分别为 85.64% 和 74.29%。另以 `postgresql_tools` 构建标签运行真实 `pg_dump` / `pg_restore` 认证恢复测试，通过新增表结构、非空手工容器与管理历史恢复；凭证/材料三表在该恢复夹具中为空，其非空来源与历史保留由升级和业务集成测试覆盖，不声称重跑 1,000 Document 演练。Web 38 项单测、14 项相关模拟浏览器测试及静态/构建检查通过，详见 `tests/evidence/manual-trips/postgresql-gate-summary.json`。

恢复首轮及诊断轮因物理列序空位导致 Schema 指纹不一致而失败；已修复并用列顺序、名称、类型、非空和默认值反例及真实恢复重验。历史静态阶段摘要保留，不将失败覆盖为通过。上述结果不是新发布镜像、全套 Lighthouse/性能发布门禁、真实 Provider 或生产部署验收。
