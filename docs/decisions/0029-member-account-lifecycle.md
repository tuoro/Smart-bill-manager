# ADR-0029：成员加入与账号生命周期

状态：已接受，B5 于 2026-09-05 本地验收通过，未发布
日期：2026-09-04

## 范围与身份边界

补齐第二名成员加入、既有四角色的分配、停用/恢复、自助改密和本地受控恢复。沿用唯一全局 User、租户 Membership 与 Session；不新增租户密码、公开注册、邮件发送、SSO、代用户业务操作或跨租户身份搜索。Owner 只管理本租户 Membership，不能重置共用 User 的密码。

邮箱使用同一 NFKC、trim、lowercase 和纯地址校验，供 bootstrap、登录和邀请复用。`0007` 为现有 Membership 增加版本，保留所有现有用户、角色和业务历史；全局规范邮箱唯一。成员列表按入库时间/用户 ID keyset 分页，默认 20、最多 100，不截断团队成员。

成员及邀请同时提供当前租户 Owner 专用的按 ID 精确读取。编辑冲突恢复不能依赖目标仍在当前分页；刷新失败保留草稿但禁止确认，刷新成功须重新核对。翻页成功后才提交游标历史。

## 邀请与加入

- Owner 经 `members.manage` 输入邮箱、四选一角色和理由创建本租户邀请，有效期固定 48 小时；不查询或透露该邮箱是否存在于别的租户。已有本租户成员（包括 suspended）不能借邀请改变角色或恢复。
- 一次性代码由现有安全随机 token 生成器产生，只存 SHA-256 hash。创建响应仅首次返回代码；相同幂等键/请求可回放邀请身份，但不会恢复代码。响应丢失或代码丢失时，在邀请列表核对后撤销并重新创建，不自动连发。
- 邀请列表稳定分页，只返回邮箱、角色、有效期、状态与版本，不含 token/hash。每个租户最多 100 个未撤销且未消费、未过期邀请；相同规范邮箱只有一个当前有效邀请。撤销需版本和理由，保留历史。
- 公开 `/join` 只让持有代码者在请求体内提交代码，不能放入 URL、查询串、storage、日志或报告。检查代码后显示它绑定的工作区、邮箱、角色及新/已有账号模式；不存在、过期、撤销和已用代码统一拒绝，不提供邮箱枚举接口。
- 新 User 设置姓名与 12～1024 字节密码；已有 User 必须验证现有密码，不得覆写全局姓名或密码。即使已有 User 的其他 Membership 全部 suspended，仍可验证全局身份加入被邀请的新租户。
- 最终消费事务锁 Tenant、邀请，再锁/创建 User，重新核对代码状态、邮箱、现有密码 hash 和 Membership；创建成员、消费邀请、审计原子提交。并发新建同邮箱账号发生冲突时须重新验证已有身份，不静默采用新的密码。重复消费不能追加成员、改变角色或签发会话。加入成功后显式登录。

## 成员与会话

成员角色/状态变更携带 expected_version、理由；在 ReadCommitted 事务中先单独锁 Tenant，再读取操作者当前 Owner 权限、目标 Membership 和最后 Owner 条件。相同状态不是一次新变更。数据库触发器同样串行核对 active Owner，不能依赖无锁 count；任何租户均不得变成没有 active Owner。

角色或状态变化原子增加 Membership.version，撤销该 tenant/user 全部会话并写审计；恢复不复活旧 Cookie，升权也要求重新登录以刷新界面能力。成员历史不物理删除。版本冲突保留页面选择与理由，刷新后要求显式再确认。

登录在事务外校验 Argon2；创建 Session 时锁 User，再锁 Membership，比较已验证的 password hash 和 Membership.version，并核对 active 状态。改密/恢复共享 User 锁，不能在旧密码已被替换后插入旧认证结果产生的 Session。不引入重复密码版本或另一套登录状态。

自助改密要求有效会话、CSRF 和当前密码；错误密码使用 `invalid_credentials`，不等价于会话失效。新密码不能等于旧密码。成功原子替换 hash、撤销该 User 在全部租户的会话并追加全局账号审计，当前会话也失效。审计只存身份、操作、理由和时间，不存密码、hash、token 或 Cookie。

已完成鉴权的在途普通业务请求可按原有业务事务边界完成；不是强制中断所有请求或 Worker。成员管理与凭据变更命令在其最终事务重新验证授权；变更提交后新请求和新登录必须按新状态判定。这个边界不得宣传为撤回已经授权的外部调用。

## 多工作区与前端状态

既有登录端点仍只在最终选定工作区后返回 Session。密码验证正确且存在多个 active Membership 时，页面调用相同凭据保护的工作区选择端点；只有验明密码后返回列表，选择后再次登录。邮箱/密码改变立即清掉旧选择；不自动选择第一个工作区。

在 client/session 唯一位置管理认证代际：业务 `401 unauthenticated` 清掉当前缓存并导航登录，旧请求不能覆盖新登录或使其失效；登录、加入、改密的凭据错误保留各自表单。网络错误不能被缓存为“已确定未登录”。公开加入页不依赖一次成功的 Session 查询。

导航提供仅 Owner 可见的“成员管理”和全角色可用的“账号与密码”。邀请代码只保存在当前组件内存；复制失败明确提示，关闭/卸载清除。按钮具名、忙碌与冲突状态明确，窄屏和键盘均可用。

## 本地账号恢复、升级与恢复工具

提供 `recover-account` 本地 CLI，由能控制该本地部署的操作者使用，不通过 Owner Web API 暴露。精确选择全局 User、填写理由并提供新密码；命令明确影响全部工作区，拒绝 bootstrap 重跑代替恢复。输入仅交互隐藏输入或 owner-only、单硬链接、非符号链接、受限长度文件；不接受密码 argv 或普通环境变量，不打印身份或凭据。运维要求先停止应用，再执行恢复并重启；不以恢复命令控制用户实例。

恢复与自助改密复用一个原子账号写用例；本地恢复在账号审计中标记 `local_operator`，不能伪造任一租户 Owner。该入口不是远程忘记密码、真实邮箱验证或新增权限提供者。本轮只在隔离合成账号运行，不能触碰用户实例。

新增邀请和全局账号审计进入认证备份与精确 Schema 验证。恢复先证明原快照完整，再撤销全部 Session 和尚未消费/撤销的邀请（保留邀请历史，标明 restore 撤销）；这是恢复激活前明确的安全状态变化，其余身份、业务及审计内容不得变化。旧代码不能在恢复后重新使用。升级测试覆盖现存用户、会话、业务记录及故障回滚。

## 验收与退出

- 无直接数据库编辑即可加入第二名成员；新/已有全局身份、多租户选择、失效/撤销/重复邀请和并发加入有真实 PostgreSQL 测试。
- 四角色权限、跨租户、最后 Owner 并发、停用/恢复旧 Cookie、降权、新密码和改密/登录竞争均有确定性测试；失败不得留下部分邀请/成员/审计。
- Web 完成邀请、加入、角色/状态确认、改密、多工作区和业务 401；覆盖迟到响应、重复点击、409 保留输入、复制失败、键盘/窄屏。
- 本地恢复的受限输入、精准身份、全局会话撤销、审计、当前镜像/CLI 接线以及认证恢复新表通过；没有真实凭据进入仓库或测试输出。
- 适用 Go/Web 全回归、关键不变量、原门槛覆盖率、静态检查、构建和浏览器通过后写聚合证据，清理本轮资源再进入 B6。

不含发版、用户实例升级、真实账号操作、新依赖或其他产品范围。
