# ADR-0031：30 天推荐与显式跨期分配

状态：2026-09-05 已完成本地验收，未提交或发布；替代 ADR-0013 的人工分配日期硬限制与全量目标上限。

## 决策与边界

- 初次 Claim 审核仍只推荐业务日期相差不超过 30 个日历日的同币种记录。已确认 Payment/Invoice 的独立分配允许人工搜索全部日期，超过 30 天明确提示，并继续强制填写 1～500 字调整理由。
- 目标查询固定每页 50 条，使用 ID keyset；默认仅查 30 天内，切换“全部日期”才展示跨期候选。按商户/购销方、单号或 ID 字面搜索；SQL 完成租户、可用性、币种、余额与日期过滤，禁止全量读入内存。
- 为稳定翻页，候选统一按 ID 升序，替代旧版名称/日期差排序；名称与日期差仍展示为提示。全部日期允许空查询浏览。游标绑定租户、锚点、视图和规范化查询；分页是当前状态视图，不宣称跨请求固定数据库快照，纠错或余额变化后可刷新首屏，提交以事务重验为准。
- 当前活动关联独立加载并固定保留在草稿中，不因搜索、翻页或超期而隐式撤销。完整期望计划仍最多 200 项；候选总数不再是提交门槛。
- 200 项完整计划要求单个 Fact 两端均至多 200 条活动 Link；`0008` 在初次确认和独立调整共用的 Link 写入处守界。第 201 条显式冲突并整体回滚；若升级前已有超限状态则迁移明确失败，报告超限待人工处理，不截断、不删除、不代替用户调整。
- 工作区在 PostgreSQL repeatable-read 快照读取。`plan_hash` 只代表锚点活动 Link 集合，不代表整个候选库；提交在 serializable 事务中按显式目标 ID 重读金额、币种、可用状态和双方余额。计划改变、目标不可用或超额须明确冲突；其他候选新增不使草稿失效。
- 财务纠错不再仅因日期差超过 30 天而强制撤销既有分配；金额、币种、可用性和影响快照校验不变。保留原件、Claim、Review 与 immutable Link/Adjustment/Audit，不直接更改 Fact。

## 验收

覆盖 30/31 天及更远日期、两侧锚点、字面搜索、超过 200 条跨页访问、跨页保留草稿、全部撤销确认、空理由、租户/权限、过期计划、并发余额竞争及回滚；旧推荐规则保持，跨期财务纠错不误拒绝。领域/PG/API/Web/浏览器与既有不变量回归通过后记录安全聚合证据。
