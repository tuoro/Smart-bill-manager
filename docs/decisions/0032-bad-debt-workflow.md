# ADR-0032：坏账标记与关联行程删除保护

状态：2026-09-05 已完成本地验收，未提交或发布。

## 决策与边界

- Owner/Finance 可对活动 Payment 或 Invoice 标记/取消坏账，必须给出理由，检查当前版本，支持幂等，保存不可变决定及安全审计。该状态是人工业务元数据，不是会计核销，不更改金额、分配余额、原件、Claim/Review 或报销资格/历史快照。
- PostgreSQL 前向迁移保存坏账当前状态及其决定历史；现有新架构数据默认未标记，纠错保留状态。不引入旧字段兼容、旧数据读取或 Trip 上的冗余锁字段。
- `0008` 的 append-only `fact_bad_debt_decisions` 是唯一状态源；按 Fact 版本索引取得最后决定，未有决定即 false，不额外保存 payments/invoices flag 或 pointer。决定写入锁定 Fact 并核对 expected version，随后递增版本；提交期校验必须恰好达到 resulting version，不能借纠错旧版本补插状态。一次事务只改变同一 Fact 的坏账状态一次。
- 行程删除保护从当前活动关系派生：直接归属于该行程的坏账 Payment/Invoice；以及分配给该行程内 Payment 的坏账 Invoice。已结束的分配/归属不参与保护。TripEvidence 不具有坏账状态。
- 标记记录仍可显式取消坏账或调整关系；不是永久法律保留锁。沿用 Fact 软删除及关系结束语义，软删除记录不再保护当前行程，历史决定和报销快照保留。保护不是删除所有相关材料的全局锁。
- 行程页面展示保护状态，删除按钮禁用并说明原因；后端在删除事务内再次检查，不能只靠 UI。标记、归属、分配、删除都使用既有 serializable 事务和相关行锁，竞争时按先后结果重试或冲突，不能删除已提交坏账仍关联的行程。
- 数据库统一函数派生保护图；坏账、活动分配和活动归属的新增入口锁定关联 Trip，删除即时检查和提交期检查共同防止同事务后续写形成已删除的受保护行程。无租户级全局锁；冲突使用既有 serializable 重试。

## 验收

两种 Fact 的标记/取消/重放/同键异参/版本与权限隔离；直接归属与发票经支付间接归属保护、结束关系解除、删除回滚、并发标记与删除、纠错保留及报销金额不变；迁移升级/重复运行/事务回滚与认证备份恢复保留状态和历史；实际 API、列表/详情/行程页面及键盘窄屏入口。

本地验收已通过，非空状态/决定历史与行程投影真实恢复，结果见 `tests/evidence/business-completion/b7-b8-allocation-bad-debt.json`。
