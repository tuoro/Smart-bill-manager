# ADR-0036：连续审核与分配草案的隔离贯通验收

状态：已完成本地组合贯通验收，含显式冲突恢复；未提交或发布
日期：2026-09-06

## 目标与范围

用户同意在行程整理前，补齐 ADR-0034/0035 当前 Web 与真实后端的联合验收。此前单元和 Mock API 浏览器通过不代表此次新界面已与实际持久化链路一起运行。本轮不新增产品功能、不调用外部模型、不读取或修改用户实例、不提交或发布。

复用已核实身份的本地 v0.4.0 后端镜像：其发布输入摘要与当前 Git HEAD 一致，且当前后端、Schema、迁移和入口代码无未提交修改；镜像构建前的 revision 标签不代替发布输入摘要核对。只读挂载本轮当前源码的生产 Web 构建。证据称“当前 Web 与既有后端镜像的组合贯通验收”，不冒充新镜像或新发布门禁。

## 隔离与数据

- 新建唯一 Compose project、空 PostgreSQL 17、对象卷和私有临时目录；按既有 provision、migrate、bootstrap-owner 创建本轮独立账号。主密钥、数据库密码、Owner 密码和模拟 Provider Key 均为本轮随机生成，只经保护文件传递，不在命令或报告输出。
- 明确使用本地 Docker endpoint，`--env-file /dev/null` 与允许清单环境，不继承用户 `.env`。使用本地已存在、身份固定的镜像，禁止拉取、构建时下载或覆盖已有镜像标签。
- 数据库不发布端口；两个 Docker 网络均为 internal，应用只经独立 loopback 端口访问。本地模拟模型与应用共享网络命名空间，只监听 `127.0.0.1:19086`。浏览器只允许本轮应用 origin，不能代理到用户后端。
- 3 张可读、明确标记“合成测试”的 PNG 与 Mock 字段相符。Mock 是固定响应，不执行识别；单 Worker 按顺序上传并等待处理，Provider 明确选择本轮模式，恰好三次提取，超出范围失败。保留真实 HTTP、规范化、Mapper、Claim、校验、Review、Fact、分配事务与重读链；不直接插入业务表、不替换浏览器 API 响应。

## 固定场景与成功标准

单据为同币种 CNY、同商户/销售方：Payment P=10000 分，Invoice A=6000 分、Invoice B=6000 分；发票号码独立，日期分别为支付前一天与当天。

1. 登录、创建并检测/激活本地模拟 Provider，逐张上传三张图片，等待三项均可审核。所有 Fact 创建必须经过本次连续审核中的明确保存；初次关联明确不分配，疑似重复若出现则逐项显式核对为独立单据，不绕过校验。
   - 实测相近版式的 B 在 A 的 Claim 创建后上传，给 A 新增视觉重复候选。固定恢复验收保留这组图片：B 已确认后，A 第一次确认必须明确返回 `409 duplicate_candidate_set_stale`，队列停在 A 且不部分创建 Fact/Link；用户通过已有“修订字段→不改字段或证据→保存修订版本”重建候选，再逐项明确选择独立单据并确认。只允许这一次、这一单据的明确预期冲突；不能吞掉其他错误或预先自动修订全部单据。
   - 新版本继承原 AiRun，未改字段仍为 AI 来源，复制证据保持溯源；不新增提取。最终为 3 次成功确认、1 次无部分写入的预期冲突、1 次显式修订，3 个 AiRun、4 个 Claim；证据称“含冲突后恢复的贯通”，不称首次直接成功。
2. 确认后实际 API 返回三份 Fact、原件/Claim/Review 来源与规范化后的正确字段。刷新/重新进入页面后仍能读取，未保存的建议不产生 Link。
3. 打开 P：两个新目标合计 12000≠10000，显示歧义、不自动勾选，也不提交。
4. 打开 A：唯一 P 目标双方余额不等，采用后金额留空；人工填写 4000（小于 6000 上限）、理由并明确保存。真实重读确认 P 已分配 4000/剩余 6000，A 已分配 4000/剩余 2000。
5. 回到 P：旧 A 的 Link=4000 保留且不建议增额，新 B=6000 正好等于 P 剩余；采用后最终请求为完整计划 A=4000、B=6000，仍须填写理由并明确保存。
6. 再次重读 P/A/B 与页面刷新：P 已分配 10000/剩余 0；A 已分配 4000/剩余 2000；B 已分配 6000/剩余 0。A 的旧 Link ID、金额不变，B 只增加一条 Link；准确数量和来源链可用本轮数据库只读聚合交叉核对。

## 实施与证据

- 仅扩展测试用 Mock Provider 的显式固定场景及单元测试；独立贯通规格不进入默认 Mock 浏览器目录，不能让缺少本轮环境的普通测试误连默认服务。
- 使用现有依赖，重型任务串行、浏览器单 Worker；本轮容器合计配置不超过 6 GiB，前后检查内存。适用工具测试、Web 类型/静态检查、生产构建和真实页面链均须通过。
- 按真实请求和响应断言，不用睡眠代替完成信号；除固定恢复场景中严格核对错误码、目标、次数和零部分写入的那一次 409 外，其他 API 错误、页面异常、模拟响应数异常均判失败，不吞错或改为成功。发现业务缺陷先明确记录，只在本轮验收必需且边界不变时做最小修复。
- 安全聚合记录源码/镜像/配置身份、场景数量、精确余额与关系计数、测试结果和局限；不保存凭据或原始账号/单据响应。销毁本轮临时容器、网络、卷、凭据、图片、构建及原始报告，保留可重复的测试代码与安全聚合。
- 本次不能证明模型正确率、总体场景收益、真实用户核对时间或 30% 时间减负目标，不包含性能、数据库备份恢复、新镜像分发或行程新功能的验收。

## 实测发现（保留失败，不回写为通过）

- 第一次运行在第一张单据处停止：测试把用于匹配的小写 `normalized_value` 当作票面 `value` 比较。修正为分别核对两者，不改产品规范化逻辑。
- 第二次运行三次提取成功，B 确认后 A 返回上述重复候选过期冲突。数据库当时为 3 个 AiRun/Claim、1 个 Invoice/Review、0 个 Payment/Link/分配调整；独立复现确认准确错误码。后端与现有 UI 的保护和恢复指引一致，不改规则、不换图绕过。本轮补齐该显式恢复验收，最终结果另行记录；每次完整重跑前均销毁并重建本轮独立数据卷。
- 第三次运行已执行显式修订成功；测试将新建修订的 `201` 错写成 `200` 而停止。已按真实 Handler 与契约修正，数据库核对当时为 4 个 Claim、3 个 AiRun，修订来源、全部字段与复制证据不变量均通过；不把该半程结果当作完整贯通。

## 验收结果

2026-09-06，第四次从独立空环境运行完整通过，单 Worker、无自动重试：1 项真实浏览器贯通、115 项 Web 单元、10 项 Provider 单元，以及 Web 类型检查、ESLint、Prettier 和生产构建通过。前两切片记录的 16 份源码及两份证据摘要未变；150 项 Mock 浏览器是 ADR-0035 的历史结果，本轮未重跑。安全聚合见 [throughflow.json](../../tests/evidence/review-allocation/throughflow.json)，复现入口见 [贯通测试说明](../../apps/web/e2e-runtime/README.md)。

- 三张合成原件均经过真实上传、规范化、Claim、连续审核和 Fact 持久化；原件授权回读摘要与上传摘要一致，规范化页已授权读取、确认非空并记录摘要。最终 4 次确认请求中 3 次成功、1 次指定重复候选过期冲突，随后经已有 UI 显式修订一次；冲突不推进队列、不部分写入，字段及复制证据保持原有 AI 来源。
- 歧义草案未自动选择；部分分配采用后金额仍为空，人工填入 4000 分并保存。随后采用 B 的 6000 分草案时，完整计划保留 A 的 4000 分，仍要求理由与明确保存。刷新重读 P 已分配 10000/剩余 0、A 已分配 4000/剩余 2000、B 已分配 6000/剩余 0；A 原 Link 完整对象未变，只新增 B 一条 Link。
- 本轮 PostgreSQL 只读聚合为 3 个文档/Job/AiRun、4 个 Claim、3 条 Review、1 笔支付、2 张发票、2 条有效 Link、0 条终止 Link、2 次补充分配。来源链、修订继承、未改字段及复制证据、调整与 Link 历史链均通过。Provider 实测 4 次请求＝1 次能力探测＋3 次提取，无新增识别。
- 最终浏览器有初始未登录的预期 401 和上述一次预期 409，其他异常 API 响应、页面异常、传输失败与外部请求均为 0；不概括为“零错误”或“首次直接成功”。前三次失败如上保留，四次运行使用相同三张图片，不换图规避保护。
- 本轮只新增/调整验收代码、静态检查范围和文档，没有修改产品业务逻辑、后端、契约或数据库迁移。当前 Web 以只读构建挂载运行，不是新镜像验收；未调用真实模型、未升级用户实例、未提交或发布。
- 已核实并删除本轮 5 个容器、2 个新建测试卷、2 个网络，停止临时 loopback 转发；凭据、图片、构建和原始报告所在私有临时目录已清理。已有镜像和用户数据保留，合成测试环境可按说明重建。容器总配置 3.75 GiB，宿主前后可用内存约 9.5 GiB；这不是峰值或性能门禁。
