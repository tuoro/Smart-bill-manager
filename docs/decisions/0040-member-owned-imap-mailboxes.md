# ADR-0040：邮箱按成员归属，服务端 IMAP 同步

状态：已接受
日期：2026-09-12

## 背景

ADR-0014 只登记邮箱描述信息、不收密码、不拉邮件，真实连接留给「未来的连接器」。角色收成管理员 / 成员两档（迁移 0014）之后，产品要求：每个成员都能添加、删除自己的邮箱，而且邮箱要真的能收票。

## 决策

### 归属

- `email_sources.created_by_user_id` 即归属人。管理员看全部；成员只看得到、动得了自己登记的。不可见时一律 404，不泄露有无。
- 邮件与附件的读取沿同一规则（对象查询带上来源归属人）。
- 邮件附件生成的 Document 仍进入工作区共用的账本，登记人算作上传人（ADR-0014 原有规则）。

### 凭据与连接

- 密码 / 授权码用主密钥 AES-GCM 加密存 `encrypted_password`，与 Provider API Key、钉钉 AppSecret 同一套；页面只知道 `has_password`，永不回显。密码不参与登记的幂等哈希。
- 保存 → 检测（登录 + 只读打开 INBOX）→ 开启同步。换密码即重置为待检测并关闭同步；检测失败也关闭同步。数据库 CHECK 保证「同步开启 ⇒ 检测通过且有密码且未删除」。
- 同步只读：不打已读、不移动、不删除。首次接入只回溯 30 天；之后按 `UIDVALIDITY + UID` 增量，一轮最多 50 封，轮询间隔 5 分钟，也可「立即同步」。
- `external_message_key = sha256("imap/1|source_id|uidvalidity|uid")`：确定、不可逆，符合 ADR-0014 对外部键的要求。
- 连接器（`adapters/imap`）只把原始 RFC 822 字节交给 `emails.Service.Archive`，仍是唯一归档入口。

### 删除

- 软删除：`deleted_at`，同时清密码、关同步。已归档邮件与由此生成的单据是不可变 Source，保留。
- 身份唯一约束改为只对未删除来源生效，删掉的邮箱可以重新登记。

## 后果

- 首次开启同步可能拉进最近 30 天的旧票，用户需在收件箱里审核；这是有意的默认，避免漏掉刚开通前的发票。
- 服务端持有邮箱凭据，主密钥丢失即全部不可用（与 Provider Key 同一风险面）。
