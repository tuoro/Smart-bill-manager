# 钉钉收单对话协议（草案）

状态：草案，待产品负责人过目。定稿后作为连接器实现依据，机器人每一句话以本文为准。

## 原则

- 常见路径一次确认；罕见路径多问几句，但每一步只问一件事。
- 回执纯文本。原件是用户自己刚发的那条消息，不回传。
- 机器人**从不代替人做决定**：不自动关联、不自动合并、不自动填字段。
- 每条回复都能独立看懂：带单据名，不依赖上一条。

## 一、绑定

| 用户 | 机器人 |
|---|---|
| 发送绑定码（网页生成） | `已绑定到 张三（合成团队）。以后直接把支付截图或发票发给我即可。` |
| 发送无效/过期码 | `绑定码无效或已失效，请在网页「账号与密码」重新生成。` |
| 未绑定就发文件 | `还没绑定账号。请先在网页「账号与密码」生成绑定码并发给我。` |

## 二、投递与回执

用户发文件（图片或 PDF）：

```
已收到 alipay-0910.png，正在识别。
```

识别完成，按可确认与否分两种：

**A. 可直接确认**（校验全过、无疑似重复、分配候选 ≤1 且金额精确吻合）

```
alipay-0910.png 识别结果：
1. 商户  星巴克（上海）咖啡有限公司
2. 金额  CNY 123.45
3. 时间  2026-09-10 12:30  Asia/Shanghai
4. 支付方式  支付宝
（有发票候选时追加）5. 关联发票  9-10 星巴克 CNY 123.45 · 唯一精确匹配

回复「确认」保存；回复要改的编号（如 2）修改；回复「作废」丢弃。
```

**B. 需要判断**（校验未过 / 有疑似重复 / 多个候选 / 金额不吻合）

```
alipay-0910.png 识别结果：
1. 商户  …
2. 金额  …
…
需要你判断：
· 有 2 笔金额相同的支付疑似重复
· 找到 3 张可关联的发票
回复「处理」逐项处理，或到网页处理：/reviews/…
```

**C. 识别失败**

```
alipay-0910.png 识别失败：图片无法读取。可重新拍一张，或到网页转人工录入。
```

重复文件：`这份文件之前已收过（alipay-0910.png，9-10 12:31）。` 不再建新任务。

## 三、修改字段

用户回编号：

```
用户：2
机器人：把「金额」改成什么？当前 CNY 123.45。
用户：132.45
机器人：金额 → CNY 132.45。（票面上写的是这个数吗？回复「是」记入，或回复票面原文。）
```

- 单页图片：证据页码固定 1，摘录默认为用户回复的值；回复「是」即采用。
- 多页 PDF：追加一问「在第几页？」。
- 校验失败即时回：`CNY 小数位不能超过 2 位，请重新输入。`
- 改完回到 A/B 结果卡（编号不变、已改项标 `（已改）`），再等「确认」。

改「币种」等同理。改「关联发票」（编号 5）走第四节。

**改「时间」有固定格式**，避免歧义引发业务日期与重复检测出错：

```
用户：3
机器人：把「时间」改成什么？当前 2026-09-10 12:30（Asia/Shanghai）。
       请按 年-月-日 时:分 回复，24 小时制，例如 2026-09-10 12:30。时区保持不变。
用户：2026-09-10 12:45
机器人：时间 → 2026-09-10 12:45（Asia/Shanghai）。
```

只接受 `YYYY-MM-DD HH:MM`；缺秒补 00；其他写法（`9/10`、`12点45`、带时区）一律拒绝并重发格式提示。时区不在聊天里改。

## 四、逐项判断

回复「处理」后，每次只处理一项：

**多个候选**
```
可关联的发票：
1. 9-10 星巴克 CNY 123.45 · 名称一致
2. 9-09 星巴克 CNY 123.45 · 名称一致
3. 9-10 星巴克 CNY 200.00 · 金额不同
回复编号关联（可多选，如 1,3），或「不关联」。
```
多选时追问每张分配金额：`1 分配多少？剩余 CNY 123.45。` 直到剩余为 0 或用户回「够了」。

**疑似重复**
```
疑似重复：9-10 12:28 星巴克 CNY 123.45（已入账）。
这是同一笔吗？回复「同一笔」作废本次，或「不是」保留为独立记录。
```

**校验未过**：按第三节逐项改。

全部处理完回到结果卡，等「确认」。

## 五、确认

```
用户：确认
机器人：已保存。支付 · 星巴克 · CNY 123.45 · 9-10。
```

不问理由。操作者对自己的操作负责，审计记录里已有谁、何时、改了什么。（网页端的理由字段同步删除，见对应改动。）

保存冲突（数据已被别人改过）：`这条单据刚被他人修改，请重新发送文件或到网页核对。`

## 六、状态与打断

| 情况 | 处理 |
|---|---|
| 一个人同时只有一条「进行中」的单据 | 新发文件即打断旧流程：`上一份 alipay-0909.png 未完成，已放回网页待审核。` |
| 20 分钟无回复 | 提醒一次：`alipay-0910.png 还没确认，10 分钟后将放回网页待审核。` 只提醒这一次。 |
| 30 分钟无回复 | 流程结束，单据留在网页待审核队列。 |
| 回复无法解析（不是编号/关键词） | `没看懂。当前可回复：确认 / 编号 / 作废。` 重复三次后结束流程。 |
| 「作废」 | 等同网页驳回：`已作废，不生成记录。` |
| 网页与钉钉同时操作同一单据 | 以先保存的为准，后者收到冲突提示。 |

## 七、不做的事

- 不回传原件。
- 除上述 20 分钟那一次外，不做其他主动提醒。
- 不在钉钉里做行程归属、报销、成员管理。

## 已定

- 时间字段可改，格式固定为 `YYYY-MM-DD HH:MM`，时区不在聊天里改。
- 一人同时只有一条进行中，新文件打断旧流程，不排队。
- 20 分钟提醒一次，30 分钟超时放回网页队列。
- 全程不问理由。
