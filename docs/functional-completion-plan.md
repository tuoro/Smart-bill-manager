## 实施顺序与切片验收

### B1：识别彻底失败后的显式人工录入

范围：已经合法上传、没有可审核 Claim 且识别任务失败的单据，由有审核权限的用户显式转人工，填写 Payment、Invoice 或 TripEvidence 所需字段，复用审核、校验、重复提示和确认流程。无原件记账、处理中抢占和对已确认单据重新识别不在本切片。

实施前决策：明确人工 Claim 的来源身份、与 Job 的状态转换以及失败于页面准备阶段的处理；不能为了满足现有非空关联伪造成功 AiRun。合法原件需要补做页面准备时只执行既有确定性文件处理，不调用模型。

验收：

- 合法原件在无可用模型或模型彻底失败后，仍能从显式人工入口完成一次审核确认；非法、损坏或无法安全读取的原件不能绕过文件边界。
- 人工输入明确标记用户来源，不伪造模型输出、票面 quote、AiRun 或 Evidence；实际发生的失败与尝试历史保留，模型失败不能被记成识别成功。
- 不新增第二套 Fact 创建或业务校验路径；仍需完整字段校验、重复处理、显式 Review 和整数金额。
- 转人工与重试、取消、删除的竞争有确定性结果；迟到 Worker 不能覆盖人工 Claim，同一原件不会形成两个活动审核或重复 Fact。
- 页面可填写、保存、恢复草稿、确认；拒绝无权限、跨租户、陈旧版本和重复提交的错误路径均有覆盖。

### B2：已确认单据的可追溯纠错

当前断点：按 [ADR-0026](decisions/0026-confirmed-fact-correction.md) 完成本地验收。三类 Fact 的预览、原子纠错、幂等回放、历史、HTTP/OpenAPI 和管理入口已实现；覆盖来源/明细历史保留、分配冲突与显式撤销/回滚、关系竞争、重复目标修订变化、自动/人工归属、材料关联及三种报销状态。`0004` 前向升级/重复执行/故障回滚和真实 PostgreSQL 17 认证 dump/restore 通过。最终 Go 回归 533 项、关键不变量 173/173、领域/应用覆盖率 86.15%、基础设施/传输层 74.97%，vet/build 通过；Web 41 项及契约/静态/构建通过，33 项 Mock API 浏览器联跑通过，另有真实数据库 HTTP 集成。证据见 `tests/evidence/business-completion/b2-fact-correction.json`；并非部署环境的联合发布门禁，未升级用户实例或提交。下一项 B3。

范围：对已确认 Payment、Invoice 和 TripEvidence 修正字段，提供原值、新值、理由及历史。B1 完成后复用人工字段与审核来源规则；不直接覆盖原始 Claim，不用删除重建代替纠错。

实施前决策：在 ADR 冻结 Fact 身份/版本协议，以及金额、日期、币种变化对分配、自动/人工行程归属、重复检测和报销引用的影响。不能只实现无关联单据而宣称纠错闭环完成。

验收：

- 未关联与已关联单据均有明确纠错路径；余额不足、类型/币种冲突、并发关系变化会显示原因，不能静默截断金额或遗失关联。
- 需调整的活动关系必须经过显式决定；Fact 和相关关系的提交保持原子性，历史版本及决定保留。
- 已提交、已报销或已驳回的报销快照不被追溯改写；界面说明其引用的是历史版本，后续流程不重复计算同一业务事实。
- 人工归属优先保留；日期纠错触发的自动归属变化可解释。详情显示当前有效值、历史修订与原件来源。
- 并发纠错、重复确认、事务回滚、重复候选变化与租户/角色边界均通过测试。

### B3：完整单据管理与详情

当前断点：按 [ADR-0027](decisions/0027-complete-fact-management.md) 完成本地验收。两类各 201 条 keyset 全遍历、字面/日期/分配筛选、一致性详情、授权来源和管理入口已实现；已删除锚点仍可继续，跨范围游标拒绝，Invoice 列表不预载明细。`0005` 前向升级/回滚及 PostgreSQL 17 认证恢复通过；Go 541 项、179/179 不变量、覆盖率 86.28% / 75.45%，Web 43 项和 89 项合成浏览器联跑通过。来源展开失败/迟到响应、返回原范围、删除确认/回焦以及四尺寸双主题已验证。证据见 `tests/evidence/business-completion/b3-fact-management.json`；未提交、发布或升级用户实例。下一项 B4。

范围：支付、发票管理页稳定分页、筛选与详情；展示完整业务字段、发票明细、关联状态及获授权的原件/审核来源，接通 B2 纠错和既有分配、删除能力。B1/B2 所需最小入口随各自切片交付，不等 B3 才可操作。

验收：

- 至少 201 条纯合成记录能在管理页全部访问；覆盖相同日期排序、分页期间新增/删除、过滤条件变化，不能静默截断或重复显示。
- 使用有界数据库查询和游标，不把全量记录载入内存；金额与状态仍来自唯一事实源。
- 可按日期、商户/购销方或单号等已存在字段查找，并按分配状态筛选；具体参数和稳定排序在契约冻结时确定。
- 从列表可进入详情、查看明细和授权原件，并完成纠错/分配等操作；无权限动作不展示且服务端拒绝。
- 查询失败不显示错误范围的旧数据；键盘、窄屏和加载/空/错误状态均可实际操作。

### B4：发票补充材料

当前断点：按 [ADR-0028](decisions/0028-invoice-supporting-materials.md) 完成本地验收。无模型辅助上传、201 条候选分页、共享对象、发布恢复、解除历史和报销固定材料集已实现；并发删除/发布补偿、三种报销状态、旧快照不回填、`0006` 前向/重复升级与回滚、非空 PostgreSQL 17 认证恢复通过。最终 Go 567 项、196/196 不变量、覆盖率 86.18% / 75.62%，Web 43 项及全部静态/构建通过；96 项合成浏览器联跑通过，测试清理调整后再验 5 项材料场景通过。安全证据见 `tests/evidence/business-completion/b4-invoice-materials.json`；本轮临时资源已回收，未提交、发布或升级用户实例。下一项 B5。

范围：给已有发票显式上传或关联受支持图片/PDF，预览、下载和移除关联；辅助材料不自动成为发票 Fact，不要求调用模型，也不修改票面金额。复用现有对象存储与鉴权能力。

验收：

- 一张发票可关联多份辅助材料，并与原件明确区分；重复添加、同租户共享对象和跨租户拒绝有确定性结果。
- 上传仍执行既有类型、大小及文件签名边界；失败补偿不留下错误关联或遗失其他材料。
- 移除关联保留审计，不删除仍被其他记录引用的对象；已提交报销所引用材料的保留规则在本切片 ADR 冻结。
- 新增存储结构进入前向迁移和备份恢复精确对象集合，不能只做页面上传入口。

### B5：成员与账号生命周期

当前断点：按 [ADR-0029](decisions/0029-member-account-lifecycle.md) 完成本地验收。邀请/加入、四角色和成员版本、全局改密、本地受控恢复、多工作区与认证代际已实现；真实 PostgreSQL 验证最后 Owner 并发、旧认证竞争、单次消费、201 条邀请与 202 名成员分页、`0007` 前向升级/回滚及非空认证恢复。最终 Go 590 项、211/211 不变量、覆盖率 86.08% / 75.87%，全包 vet/build 通过；Web 50 项、契约/静态/构建及工具 62 项通过。104 项 Mock API 浏览器联跑通过，提示框布局修正后 7 项 B5 复验通过，四尺寸双主题截图已检查。证据见 `tests/evidence/business-completion/b5-member-accounts.json`；这些是组件浏览器与独立数据库 HTTP 验收，不冒充部署环境联合发布门禁。B6 后续完成情况见下一节。

范围：首个 Owner 之后的成员加入、角色分配、停用/恢复、用户自助改密码及受控账号恢复；仅使用现有四角色，不恢复旧管理员跨用户代操作、公开注册、真实邮件通知或企业 SSO。

实施前决策：结合全局 User 与租户 Membership 的边界确定成员邀请/加入和账号恢复方式。租户 Owner 不能因此取得重置其他租户共用身份密码的权限；是否需要本地离线恢复入口在 ADR 中明确。

验收：

- 新安装无需直接改数据库即可加入第二名成员，并通过各角色完成允许的业务操作。
- 最后一个 active Owner 不能被停用或降级；并发操作也不能留下无 Owner 的租户。
- 成员停用、降权和密码变更后，既有会话按冻结策略失效；旧密码/失效邀请不能继续生效，错误不会泄露其他租户身份。
- 自助修改验证当前身份，恢复方式受控且可审计；凭据或邀请令牌不进入普通日志、报告或证据。
- 只用隔离合成账号验证，不修改用户运行实例的真实成员或密码。

### B6：报销材料交付包

当前断点：按 [ADR-0030](decisions/0030-material-delivery-packages.md) 完成本地验收。当前行程与固定报销两种精确范围、201 条跨管理页边界、共享文件去重、旧快照披露、流式 64 MiB 打包、准备槽位/取消/过期/单次下载、四角色/租户/会话边界及缺件/损坏整包失败均已实现；认证 PostgreSQL 17 恢复确认临时导出目录不进入备份且恢复后为空。最终 Go 625 项、227/227 不变量、覆盖率 86.20% / 75.89%，全包 vet/build 通过；Web 50 项及契约/静态/构建通过，112 项 Mock API 浏览器联跑通过。证据见 `tests/evidence/business-completion/b6-material-exports.json`。B1～B6 计划已本地完成，但单列待决策项、真实模型/邮箱联调、发布与部署不在此结论内。

范围：按用户显式选择的行程/报销范围生成 ZIP 材料包，包含支付原件、发票及补充材料和说明清单；不是数据库备份、旧格式兼容或新报表设计器。不增加 PDF 排版、外部上传或报销系统同步。

实施前决策：明确导出当前行程材料还是固定报销快照的界面选择及精确文件清单，不能把历史报销与现有材料混成不明版本。此切片进入实施前需明确替代历史 M3 导出排除条款。

验收：

- 文件清单与所选范围、版本及权限一致，同一对象不会重复打包；不会包含无关行程或租户的材料。
- 缺失或无法读取的材料必须阻止成功结果并给出可定位的业务提示，不能静默漏文件生成“完整包”。
- 文件名经过安全规范化并处理重名；大包采用流式或受限临时文件，不能把全部文件载入内存；取消、断连和失败后回收本轮临时产物。
- 包内仅包含用户选择交付的业务材料；不包含数据库、凭据、Provider 原始响应、运行日志或内部备份内容。

### B7：跨期手工分配

用户单独授权，以 [ADR-0031](decisions/0031-manual-allocation-date-window.md) 为准。30 天保留为初次审核及默认推荐窗口；已确认 Fact 支持全部日期的字面搜索、50 条 keyset 分页和有理由的跨期分配。当前活动目标与跨页已选草稿保留，余额、币种、快照、权限及双方 200 条活动 Link 上限不放宽；跨期字段纠错不误撤销已有分配。验收包含 201 条候选完整访问、并发和回滚，以及实际页面操作。

### B8：坏账及行程删除保护

用户单独授权，以 [ADR-0032](decisions/0032-bad-debt-workflow.md) 为准。Payment/Invoice 的人工标记与取消必须有理由、版本及幂等身份；不可变决定是唯一状态源。保护实时派生自直接归属和经 Payment 的发票分配，只禁止删除仍关联坏账的 Trip，不改金额、报销资格或历史快照。验收包含两类型/四角色、关系解除、并发删除、升级回滚及非空坏账历史的认证恢复。
