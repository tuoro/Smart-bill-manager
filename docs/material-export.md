# 材料包导出

适用范围：`v0.4.0` 及后续新架构版本；`v0.3.4` 不含本功能。

## 从哪里开始

管理员和财务角色可在行程详情选择“导出当前行程材料”，或在报销详情选择“导出此报销快照”。拥有单据列表权限但无原件权限的账号不能导出完整包。

先查看范围、去重后的文件数量、总大小与全部文件清单，再确认准备 ZIP。准备成功后五分钟内点击下载一次；这是浏览器原生下载，保存位置由浏览器决定。页面提示交接不等于保存完成，最终结果查看浏览器下载列表；下载失败或取消后需要重新预览准备，不支持续传。

## 两种范围不能混用

| 入口 | 包含 | 不包含 |
| --- | --- | --- |
| 当前行程 | 所选行程全部活动支付、发票原件、行程凭证、所含发票的当前辅助材料 | 其他行程、仅由日期推荐的单据、没有明确归属的关联支付或发票 |
| 固定报销快照 | 提交时选择的原件及当时固定的发票辅助材料，说明中使用固定字段和提交快照版本 1 | 未选择的单据、当前 TripEvidence、后来新增附件或纠错后的当前字段 |

老快照若没有记录当时的辅助材料集合或审核版本，预览会说明并要求明确确认。系统只导出已知原件，绝不把当前材料补成历史。行程包不受页面筛选或当前加载页数影响；同一份原件被多个项目引用时只打包一份，所有业务引用保留在清单中。

ZIP 内包含 `materials/`、`manifest.json` 和中文 `说明.txt`。它是已确认预览时点的副本，不是数据库备份，也不是下载时的实时列表；报销状态变化不会改变固定快照的清单 hash。支付与发票可能描述同一笔业务，不能直接把两类金额相加作为报销总额。

## 失败与资源边界

- 范围或版本变化时重新预览并核对；原件缺失、无法读取或哈希变化会阻止整个包，不会静默漏件。
- 每包最多 5,000 个业务引用、1,000 份不同文件、512 MiB 原件；实际 ZIP 上限 520 MiB。超过限制明确拒绝，不截断。
- 每个应用进程最多两个包同时处于准备、待下载或下载状态。准备最多两分钟，待领取五分钟，单次下载最多十分钟；及时下载或关闭无用导出以释放名额。
- 准备中可以取消。取消响应未知时页面明确提示，不冒充取消成功；未领取的孤立包仍会在五分钟内失效。离开页面或服务重启不保留可继续领取的业务任务。
- 包只能由准备它的同一有效登录会话领取，改密、退出、角色变化或重新登录后需重新准备。包 ID 不是免认证分享链接。

应用在既有 `SBM_OBJECTS_PATH/export-spool/` 中创建 owner-only 临时文件，立即解除文件名后流式写入磁盘；不会在浏览器或 Go 堆内整包缓存。该目录与权威 `objects/` 并列，沿用同一个持久化挂载，无须新增 Compose 卷；请为两个包预留约 1,040 MiB 磁盘。下载结束、断连、过期、关闭或进程退出释放临时文件。

`export-spool/` 不进入认证备份。启动只清理本实现的零字节创建窗口残留；未知或非空文件需操作者核对，不能直接清空对象根目录。导出的业务材料可能包含财务信息，请只向有权接收者交付，不把包或其中明细上传到项目问题报告。
