## 隔离与资源执行规则

门禁只在新 owner-only `/tmp` 根目录使用一次性随机本地主密钥、Owner、数据库和 synthetic Provider 密码；凭据值只走受保护文件和进程内传输，不进 argv、普通环境、日志、仓库或证据。exercise UUID 是无认证能力的合成运行标识，按既有验收工具传递，仅保存在本轮隔离配置，不进入提交或公开证据。沿用现有工具的公开合成数据，不连接真实 Provider、邮箱、远程数据库，不下载资源或发生费用。

重型工作严格串行，Go `GOMAXPROCS=2`、`-p 1`，浏览器单 Worker；单容器不超过 4 GiB，同时运行的本轮容器配置不超过 6 GiB。每阶段前后检查可用内存/Swap，异常持续增长或 OOM 即停止，不扩容重试。每阶段及时销毁不用的容器、网络和卷；最终删除本轮凭据、数据、原始报告和构建工作区。已有 `smart-bill-manager:local` 标签若为固定工具暂时指向候选，结束后恢复原镜像；用户运行实例始终保持原 image ID。

### 当时确认的发布阻断

`apps/api/cmd/backup/backup.go` 在 `pg_restore` 提交之后才执行会话失效，再分别发布对象树与主密钥；期间没有持久化恢复状态。`postgresql.Open` 只校验连接和迁移，server 与 bootstrap-owner 不检查恢复是否完整，entrypoint / localstorage 还会创建缺失的对象目录。因此，数据库恢复后到会话失效前中断，可能留下有效旧会话；对象与密钥发布完成前失败，也可能启动不配套的副本。这是根据完整调用链确认的缺口，本轮未注入实际崩溃，不伪称已有故障复现测试。

`tools/write-backup-evidence.mjs` 固定输出 `crash_safe_restore_state: true`，而现有成功恢复用例没有验证上述失败窗口。历史 JSON 不改写，但该字段不能继续作为通过依据。独立 verify 要求也必须以额外 scratch 恢复语义核对完成，不能由 `pg_restore --list` 代替。

后续授权已由 ADR-0033 冻结方案；当前已实施数据库唯一状态、启动/账号入口配对检查及故障注入测试，证据生成器消费实际 Go 测试结果，不接受缺失、失败或跳过用例。只有新候选全部受影响门禁与 scratch 独立恢复通过后，才可进行已授权的远端分发。上一轮失败和历史证据保持原身份。

### 验收中发现的工具修正

浏览器复验发现离线产物的 `web/assets` 子目录继承 `0700`，root 资产清单检查通过但运行用户无法读取，页面静态资源返回 500。本轮打包统一将镜像内公开 Web/Poppler 目录归一化为 `0755`（文件权限不变，隔离根仍为 `0700`），镜像门禁新增 UID 10001 实际读取检查。失败候选的报告保留原身份，修复后重新构建并运行候选门禁。

完整浏览器复验另外修正两处旧测试定位：独立成员页面使用已配置 `baseURL`，不再写死开发端口；账单场景按包含已确认 Fact ID 的详情链接定位，不再要求 UI 展示内部 UUID。用例和业务断言均保留，全部 120 个场景须重新通过。

ADR-0033 复验中随机 32 字节主密钥曾因末字节为 LF 被文本换行规范化截短。Go 读取器和 Docker 入口统一优先识别恰好 32 字节的原始格式，完整保留随机材料；文本 hex/base64 仍允许单个行尾。回归覆盖原始密钥的全部 256 种末字节及 Docker 的 LF/CRLF 两个实际入口场景，不能靠重新生成密钥避开失败。

旧性能造数器未写 `ReviewDecision.fact_type`，在新增修订约束下以 `invoice_item_revision_mismatch` 整体回滚。造数器须显式绑定确认类型、Fact 当前 Review 与明细 Review，保留完整 10,000 Fact/Source/Claim/Review/Origin 链与全部数据库约束；不得通过禁用触发器、空明细或缩小数据集绕过。修正后增加造数契约回归，再重新构建身份匹配的候选并执行受影响门禁。

性能脚本原先在上传后立即删除同一文档，可能与 Worker 的版本 CAS 冲突并返回 409；修正为在计时样本采集后等造数 Provider 的任务在能力摘要边界明确终止，再执行清理。首版同步修正误将该造数边界预期为 `provider_config_missing`，实际造数器包含用于历史链的活动 Provider，固定虚构 Schema 摘要应触发 `provider_capability_stale`；已据造数器及 Worker 的唯一实现纠正并增加拒绝其他失败的断言。删除失败仍直接失败，不吞错或重试冲突；上传/确认样本数、并发、Server-Timing 及查询阈值保持不变。最终完整性能复验仍须通过，先前失败不计入通过证据。
