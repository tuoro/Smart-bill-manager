# v0.5.0：应用内初始化与单一 Docker 安装路径

状态：本地发布门禁通过；远端分发状态以不可变 `v0.5.0` Tag / GitHub 预发布为准
日期：2026-09-08

## 范围

把单机安装收敛为两条 `docker run`，并把数据库连接与管理员创建移入应用内的一次性初始化页。同时落库 ADR-0034～0036 的连续审核、分配草案与组合贯通切片。不新增业务范围，不改变 Source → Claim → Fact 边界与 Fact 创建权限。

只分发 `linux/amd64` 的源码提交、不可变 `v0.5.0` Tag 与公开 GHCR 同版本镜像。不更新 `latest`、不重写历史、不升级用户运行实例或访问其业务数据。

## 安装方式变更

- 引导式安装器（`install-self-hosted.sh`）、准备器、`sbm-deploy.sh` 与版本化部署包已删除。ADR-0022、ADR-0023 标记为被取代。
- 安装改为：创建一个自定义 Docker 网络、启动 PostgreSQL 容器、启动应用容器，随后在浏览器完成数据库连接与管理员创建。
- 数据库连接可继续用 `SBM_POSTGRES_HOST` 等环境变量预先指定，其优先级高于页面写入的配置；Owner 可在「系统 → 数据库连接」中查看与修改，改后需重启应用容器。
- 未挂载 `sbm_master_key` 时，入口脚本在 `/var/lib/sbm/secrets/master-key` 生成主密钥，并要求该目录来自挂载卷。**主密钥与数据同卷，必须另行复制保管**，这与旧安装器路径下主密钥独立托管的边界不同。

## 升级边界

现有 `v0.4.0` 部署的持久数据保留。应用启动时检查迁移状态：全新库直接初始化；存在未执行迁移时拒绝启动并给出待执行条数，需先创建并独立验证备份，再以 `SBM_ALLOW_MIGRATION=true` 重建容器应用迁移。镜像比数据库旧时始终拒绝启动，不受该变量影响。

沿用旧安装器与 Compose 的既有部署不受本次删除影响：其本地副本继续可用，升级路径不变。

## 单角色边界

`docker run` 路径为单角色部署：应用使用的数据库账号同时具备建表权限，`sbm_admin` / `sbm_migration` / `sbm_runtime` 三层权限分离不在该路径上。应用被攻破时攻击者可直接修改表结构。该权衡已在部署指南开头显式标注。

## 本轮发布门禁

1. Poppler 26.05.0 由源码重建，源码 SHA-256 与仓库固定值 `6fef27ff04f3…` 精确一致；在只读、UID 10001、无网络、无 capability 约束下验证 `pdfinfo` 与 `pdftoppm` 可执行。
2. 固定 Node v24.19.0（官方 SHASUMS 校验）与 Go 1.26.7 禁网容器构建产物：336 个文件，`identity.env` 八项身份字段与镜像期望一致。
3. `check-release-image.mjs check`：`failed_gate_count: 0`。
4. 照 README 两条 `docker run` 实跑：主密钥自动生成、数据库连接检测与保存、自动建表、管理员创建、登录进入应用；重启后保持已配置状态，`/api/v1/ready` 返回 200。卷内 `config`（`sbm:sbm 0700`）、`secrets`（`root:sbm 0710`）、`objects`（`sbm:sbm 0700`）权限符合设计。
5. Go 与前端全量测试、完整 Playwright 套件 146 个用例、ADR-0036 隔离贯通验收通过。

## 已知偏差

本轮 Poppler bundle 在 Debian 13 构建，链接 `libjpeg.so.62`；`v0.4.0` 所用 bundle 链接 `libjpeg.so.8`（Alpine ABI）。功能等价且门禁全过，源码摘要一致，但产出的二进制不同，因此 `release_input_sha256` 无法与历史构建逐字节对比。仓库内仍缺少 Poppler bundle 的构建配方，应补入后再谈可复现构建。

ADR-0036 的隔离贯通验收本轮以私有覆盖配置执行（`default` 网络非 internal、直接发布回环端口），未使用 `run-acceptance-loopback-bridge.mjs`。数据库网络仍为 internal 且未发布端口，数据交叉核对与 ADR 基线一致；如需正式验收证据应按原配方重跑。
