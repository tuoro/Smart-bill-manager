# v0.6.0：两档角色、成员自有邮箱与钉钉聊天审单

状态：本地发布门禁通过；远端分发状态以不可变 `v0.6.0` Tag 与公开 GHCR 同版本镜像为准
日期：2026-09-13

## 范围

把权限收敛为管理员与成员两档，让每个成员拥有自己的邮箱来源并接上真实 IMAP 同步，并把钉钉收单从「只能上传」补成「在聊天里把单据审完」。同时修掉一批真机使用中暴露的移动端与审核页问题。不改变 Source → Claim → Fact 边界，聊天与邮箱都只产生候选，正式财务事实仍只能由人在确认时创建。

只分发 `linux/amd64` 的源码提交、不可变 `v0.6.0` Tag 与公开 GHCR 同版本镜像。不更新 `latest`、不重写历史、不升级用户运行实例或访问其业务数据。

## 角色收敛

原先的五档角色（owner / admin / finance / reviewer / viewer）收敛为 `owner`（管理员）与 `member`（成员）两档。迁移 `0014_two_roles.sql` 就地改写既有 membership 与未使用的邀请，并重建七个作用域触发器函数。

成员拥有原财务角色的全部能力，另外获得管理自己邮箱来源的能力。只读与审核员两档被删除：它们在单机自托管场景下没有实际使用者，却让每个触发器都要多枚举两个角色。

随之删除的还有「审核员确认时自动归属」这一特例：归属现在只由行程时间规则、关联规则与人工指定三条路径产生。

## 成员自有邮箱与真实 IMAP

邮箱来源改为按成员归属，成员可以自行增删自己的邮箱。凭据以主密钥加密存储，连接检测通过后才允许开启同步。同步按 UID 增量推进，首次回看 30 天，游标只在消息成功入库后前移，因此中途失败不会跳过邮件。软删除后同一身份可以重新添加。

设计与边界见 ADR-0040。

## 钉钉聊天审单

钉钉收单从「把文件转成候选」补成完整对话：机器人回卡片列出抽取结果，用户可以按编号改字段、处理重复件、选择候选分配对象、填写分配金额，然后在聊天里直接确认或作废。发「菜单」可以随时呼出当前可用操作、待办与缺发票的支付。

一个人同一时刻只保留一份在办单据，20 分钟提醒、30 分钟过期。作废会连同原件一起删除。

## 已确认关联的自动归属

支付记录与发票一旦互相确认关联，其中一方归属到行程时，另一方自动跟随，规则版本 `trip-link-attribution/1`。规则是事件驱动的，因此对上线前已存在的关联无效；应用启动时会做一次漂移核对，用同一条运行时规则补齐历史数据，不在 SQL 里重复实现一遍。

## 其他

- 作废单据会删除原件，代价是不再保留被拒绝件的审计原件，该取舍为显式选择。
- 被丢弃的单据（作废、驳回、失败）不再参与重复检测，也可以在收件箱里手工删除原件。
- 金额改为按元输入；除坏账外的操作理由改为可选。
- AI 供应商配置支持编辑与删除。
- 移动端修复：iOS Safari 日期输入框不再比同列其他输入框宽，导航抽屉不再把顶栏压成灰带，行程凭证面板与全站空态统一。
- 新增 GitHub Actions 合成检查工作流；补上 Poppler bundle 的构建配方。

## 升级边界

从 `v0.5.0` 升级需要执行 5 条迁移（0014～0018）。迁移原地修改数据且不可回滚：`0014` 会改写既有成员的角色，`0017`/`0018` 新建聊天会话表。按部署指南创建并独立验证备份后，再以 `SBM_ALLOW_MIGRATION=true` 重建应用容器。镜像比数据库旧时始终拒绝启动，不受该变量影响。

单角色部署边界与 `v0.5.0` 一致：`docker run` 路径上应用使用的数据库账号同时具备建表权限。

## 已知偏差

初始化完成后重复 `POST /api/v1/setup` 会被正确拒绝（`setup_already_complete`，不产生第二个 Owner），但 HTTP 状态码是 500 而非 4xx。该错误码映射缺口自 `v0.5.0` 起存在，本轮未修以免重做整条发布输入链，应在下一轮修正。

本轮 Poppler bundle 与 `v0.5.0` 同样在 Debian 13 构建，源码摘要一致；仓库内已有构建配方，但仍未做跨机器逐字节可复现构建的验证。

真实模型正确率、真实邮箱大规模联调、TLS/域名与生产部署仍未完成，本版本不应视为生产稳定版。
