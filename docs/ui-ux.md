# UI/UX 设计基线

状态：M0、M1 已完成；M2 进行中
视觉选择：02「国内大厂中后台」
视觉方向确认：2026-08-27
四页基线批准：2026-08-27
批准范围：视觉与交互方向、四页页面骨架、状态表达和 `docs/acceptance.md` 当前量化指标；技术证据单独记录

## 体验定位

新界面是任务驱动、状态明确、信息密度可控的 AI 财务工作台。它采用国内成熟企业工具的导航效率和结构化表达，但不复制任何具体公司的品牌、资产或完整组件外观。

参考只承担以下职责：

- 飞书/字节体系：清晰的应用框架、任务效率和过程反馈；
- Semi Design：高密度表单、表格和状态语义；
- TDesign：企业工具的稳定层级与可预测交互；
- Stripe：金额、日期、标识符和审计信息的金融语义。

“国内大厂中后台”只定义产品语言，不引入大型组织审批、复杂 RBAC、工作流编排或运营驾驶舱等范围外能力。

## 信息架构

全局框架固定为“品牌顶栏 + 分组侧栏 + 页面工作区”。主导航分组为：

1. 工作台：首页、AI 收件箱、待我审核；
2. 财务数据：支付管理、发票管理、行程与报销、数据分析；
3. 来源：邮箱来源；
4. 系统：AI 配置、系统设置。

顶栏承载产品身份、全局搜索、创建入口、帮助、通知和用户菜单；页面级操作不能塞入顶栏。M1 只暴露登录、AI 收件箱、待我审核、支付管理、发票管理和最小设置入口。未实现导航不得以空页面伪装完成。

## 页面骨架

- 顶栏高度基线为 52px，使用克制品牌蓝；全局搜索居中，通用操作靠右。
- 侧栏在宽度不小于 1,280px 时显示 196px 完整分组，在 768–1,279px 时折叠为 64px 图标栏并提供可访问名称。
- 内容画布使用冷灰背景与白色工作面板；页面顺序固定为面包屑、标题与元信息、页面操作、必要的过程状态、主工作区。
- 主要内容间距在不小于 1,024px 时为 24px，在 768–1,023px 时为 16px。
- 1,440px 及以上的审核工作台使用“原始单据 / 结构化字段 / 校验与关联”三栏；1,024–1,439px 保留原件与字段双栏，校验区移至下方；768–1,023px 允许纵向编排，但证据定位和最终动作必须始终可达。
- 小于 768px 不是 M1 正式操作端，采用单列容错布局，不得出现横向溢出、不可关闭遮罩或无法返回的状态。

## 视觉 Token 基线

- 品牌主色：`#2F5FD0`；深色模式品牌主色：`#224AAB`。
- 浅色画布/表面/边界：`#F4F6F9` / `#FFFFFF` / `#DCE1E8`。
- 浅色主文本/次文本：`#1F252D` / `#596572`；次文本在实际表面上仍必须逐项达到 WCAG 2.2 AA。
- 成功、警告、错误必须使用独立语义 Token，并同时提供图标或文字；不得直接复用品牌蓝表达业务结果。
- 字体使用系统无衬线字体栈；正文默认 14px，辅助信息不少于 12px，页面标题基线 24px。
- 间距以 4px 为基本单位，主节奏为 8/12/16/24/32；控件最小可点击尺寸为 32×32px，核心动作不小于 40px 高。
- 圆角只使用 4/6/8px 三档；面板默认 6px，不使用胶囊形容器包裹普通内容。
- 主内容通过背景和 1px 边界分层；阴影只用于弹出层、抽屉和原始纸张预览。
- 金额、数量、时间和标识符使用 `font-variant-numeric: tabular-nums`。
- 深色模式使用同一语义层级重新映射，不允许直接反色；四个代表页面必须分别验收浅色和深色。

高保真对比稿为缩放后的评审画布；其中用于容纳整页的微缩字号不直接成为生产字号，生产实现以上述 Token 基线为准。

## 核心交互模式

- 页面过程明确显示“上传完成 -> AI 提取 -> 人工审核 -> 生成事实”；步骤只表达真实状态，不作为装饰。
- 点击结构化字段必须定位原件证据，并同时展示页码或区域标识。
- 规则校验、关联候选和阻断原因使用稳定分区，不与字段编辑混成同一信息流。
- 每个任务区域只有一个主操作；驳回、返回和更多操作保持次级。任务重试只出现在明确失败状态，不放在审核终态动作中。
- 最终动作区汇总通过项和待判断项；确认后同时更新状态、过程步骤和结果反馈。
- 对话框只用于需要中断上下文的确认或短表单；详情、审核和连续编辑优先使用页面或侧栏。

## 四个代表页面

### 登录

- 左侧用一句产品承诺解释 Source/Claim/Fact；
- 右侧只提供必要认证字段；
- 不展示虚构统计、客户 Logo 或营销轮播；
- 错误与字段关联，密码和提交状态可由键盘操作。

### AI 收件箱

- 队列是主内容，不用 KPI 卡片占据首屏；
- 每行显示来源、类型、状态、时间和需要用户处理的原因；
- 上传入口明确，但不压过当前任务；
- 可区分处理中、待确认、部分结果、失败、取消和已完成。

### 审核工作台

桌面采用三段式：

```text
原始图片/PDF | 字段与证据 | 校验、关联与确认
```

- 选择字段时定位对应页和证据；
- AI 原值、用户修订值和错误原因可区分；
- M2 候选分配使用多选行，每个已选候选都有标签明确的分配金额输入；未选择分配或“不关联任何候选”前确认动作禁用；
- 关联区始终展示新 Fact 总额、本次分配合计和分配后剩余金额；每个候选展示目标总额、已分配、剩余、日期和名称匹配警告，不用颜色单独表达余额状态；
- 金额错误通过与输入绑定的文字说明暴露；零、负数、非整数、超过候选余额或本次合计超额时不能提交，也不能由前端静默截断；
- 主操作只有确认，驳回和返回收件箱是次级动作；
- blocked 状态不能通过客户端交互绕过。

在 768–1,023px 下改为原件与字段双栏，校验与关联使用下方全宽面板；小于 768px 退化为单列容错布局，不做原生移动端产品设计。

### 账单列表

- Payment 与 Invoice 使用一致的筛选和表格语言；
- 金额右对齐并使用等宽数字；
- 状态、日期、商户和关联信息保持稳定列；
- M2 在 Payment 与 Invoice 列表使用稳定列展示“已分配 / 总额”和 `未分配`、`部分分配`、`已分配` 文字状态；
- 详情使用路由或侧栏，不为每个操作打开对话框；
- 空状态直接说明下一步，不放装饰插画。

## 设计系统原则

- 使用产品自己的 Token 和无样式交互基础，不继承 PrimeVue 默认视觉。
- 字体层级不超过五级；正文默认不少于 14px。
- 间距基于 4px，主要节奏为 8/12/16/24/32。
- 主内容边界优先使用 1px 线和背景层级，避免大面积阴影。
- 金额、数量、时间和标识符使用 tabular numbers。
- 动效用于解释状态变化，常规过渡 120–200ms；尊重 `prefers-reduced-motion`。
- 颜色不是唯一状态信号；错误、警告和成功同时提供图标/文字。
- 深色模式必须由同一语义层级推导，不是简单反色。

## 明确禁止

- 满屏独立 Card；
- 蓝紫渐变、发光边框和“AI 魔法”装饰；
- 每个操作都打开 Dialog；
- 过多圆角、Tag、彩色状态和巨大图标；
- 无决策价值的 Dashboard 图表；
- 默认组件库质感；
- 只有演示数据时才成立的布局；
- 把模型置信度百分比作为可信程度展示。

## 状态矩阵

状态按业务适用性覆盖：

- 登录：默认、凭据错误、提交中、权限不足；
- AI 收件箱：混合队列、处理中、部分结果、待确认、失败、取消、空、离线/重连；
- 审核工作台：待审核、阻断、版本冲突、加载中、已完成；
- 账单列表：有数据、加载中、空、权限不足。

状态必须使用真实组件布局验证，不能只写在 Story 名称或设计说明中。

## 可访问性

- 核心流程满足 WCAG 2.2 AA；
- 完整键盘操作和可见焦点；
- 页面标题、区域、表格和表单语义正确；
- 错误消息通过 `aria-describedby` 或等价关系绑定字段；
- PDF/图片证据具有文本替代或可访问字段摘录；
- 焦点不会被抽屉、弹层或异步刷新丢失；
- 200% 缩放下核心操作可用。

## 视觉验收

视觉方向、四页设计和量化指标批准门禁已经满足。以下内容由本次批准冻结：

1. 品牌顶栏、分组侧栏、页面工作区和显式流程状态组成的全局骨架；
2. 登录、AI 收件箱、审核工作台和账单列表的内容优先级与主次操作；
3. 加载、空、处理中、部分结果、阻断、失败、取消、权限不足、离线和版本冲突的表达方式；
4. 本文定义的颜色、字体、间距、边界、圆角及浅色/深色语义。

影响上述内容的结构性变更必须重新获得产品负责人批准。M0 的 768、1,024、1,440、1,920px、键盘操作、200% 等效 reflow、浅色/深色和 WCAG 2.2 AA 结果记录在 `docs/m0-evidence.md`；M1 页面实现仍需使用批准基线和人工交互共同验收。

M0 独立复审已清零 blocker、major 和 minor，`docs/roadmap.md` 已标记完成。产品负责人已于 2026-08-27 明确授权 M1；正式页面组件必须继续遵守本基线并通过 M1 验收。
